# Dashboard Safe open-order read

The dashboard displays open orders after a connected Polygon signer signs a short-lived, origin-bound message. The message authorizes an order read, not an order or transaction. The server verifies that the funder is the CREATE2 Gnosis Safe for the signer before using its private bearer token to query the dedicated order-reader Worker. The token and CLOB credentials never go to the Dashboard. This message is time-limited to two minutes but is not single-use; anyone who obtains the message and signature during its lifetime could replay that read. Never log the proof, signature, bearer token, credentials or order payloads.

Deploy only after configuring `ORDER_READER_URL` and `ORDER_READER_TOKEN` as server-only environment variables on Vercel. The URL is fixed to the already deployed reader host in code. The token must match the reader's `ORDER_READER_TOKEN` secret and have at least 32 characters. For each Safe the Worker also needs `CLOB_ACCOUNT_1` (or `_2`, `_3`) configured as described in README.md. The account JSON contains L2 credentials; these are not read-only by nature and must be treated as trading credentials. Never paste those values into chat, logs or GitHub. The current Worker accepts GET only.

A missing Reader, wallet credentials, stale snapshot, upstream error or mismatch is an error, never an empty order list. Empty orders do not verify ownership. The Reader can return only orders available to the authenticated identity; compare them with Polymarket for each account before treating the snapshot as complete account coverage. This initial screen displays orders but does not calculate available shares, place or cancel orders, or integrate the dry-run planner. The existing Reader rejects an unpaginated array unless its completeness is independently established.

For local validation: `node --import tsx --test tests/safe-order-access.test.ts` and `node --test workers/order-reader/test-order-reader.mjs`. User signature and live account access must be tested separately.
